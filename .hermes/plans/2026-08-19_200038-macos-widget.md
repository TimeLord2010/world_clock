## Task 3: Implementar o cálculo de luz solar em Swift

**Objective:** Portar `SunShading` (lib/world_sun.dart) para Swift — mesmas fórmulas, mesmo resultado.

**Files:**
- Create: `macos/WorldClockWidget/SunShading.swift`

**Conteúdo (port direto):**

```swift
import Foundation

enum SunShading {
    /// Declinação solar em radianos (positivo = verão no norte).
    static func declination(dayOfYear: Int) -> Double {
        23.44 * .pi / 180 * sin(2 * .pi * Double(284 + dayOfYear) / 365.25)
    }

    /// Brilho 0..1 em (latDeg, lonDeg) no instante `now`.
    static func intensity(latDeg: Double, lonDeg: Double, now: Date) -> Double {
        let cal = Calendar(identifier: .gregorian)
        let utc = TimeZone(identifier: "UTC")!
        let comps = cal.dateComponents(in: utc, from: now)
        let dayOfYear = cal.ordinality(of: .day, in: .year, for: now) ?? 1
        let decl = declination(dayOfYear: dayOfYear)

        let hours = Double(comps.hour ?? 0) + Double(comps.minute ?? 0) / 60
            + Double(comps.second ?? 0) / 3600
        let hourAngle = (hours + lonDeg / 15 - 12) * 15 * .pi / 180

        let lat = latDeg * .pi / 180
        let sinAlt = sin(lat) * sin(decl) + cos(lat) * cos(decl) * cos(hourAngle)
        let alt = asin(min(max(sinAlt, -1), 1))

        return min(max(alt / (12 * .pi / 180), 0), 1)
    }
}
```

**Verificação (crítica — paridade com o Dart):**
1. Gerar valores de referência do Dart: pequeno script/`dart run` que imprime `SunShading.intensity(lat, lon, t)` para ~10 pontos (ex.: (0,0) 12:00 UTC equinócio; (0,0) 00:00; (90,0) solstício junho; (-90,0); (-23.55, -46.63) São Paulo em 3 horários)
2. Rodar o MESMO cálculo no Swift (script `swift` de linha de comando com o SunShading.swift) e comparar: diferença < 1e-9
3. Commit: `feat: port SunShading to Swift (parity-checked against Dart)`

> **Nota:** `cal.dateComponents(in: utc, from:)` + `ordinality` dão o dia do ano exato igual ao Dart (`difference(DateTime.utc(year)).inDays + 1`). Validar nos valores de referência.

## Task 4: Implementar a renderização do mapa em Swift

**Objective:** Desenhar o mapa dot-matrix com luz solar — visual idêntico ao app.

**Files:**
- Create: `macos/WorldClockWidget/WorldDotMapRenderer.swift`

**Conteúdo (estrutura):**

```swift
import SwiftUI
import WidgetKit

struct WorldDotMapRenderer {
    /// Dots [lon, lat] carregados do JSON embutido.
    let dots: [(lon: Double, lat: Double)]
    /// Dots pré-decimalizados para o tamanho do widget (stride por área).
    /// Lógica igual à do app: stride 1/2/4 pela célula que contém o dot (floor).
    var keptIndices: [Int] = []

    /// Gera a imagem do mapa (fundo #111111, dots laranja #FF9800 com brilho da luz).
    func render(now: Date, width: CGFloat, height: CGFloat, dpr: CGFloat) -> UIImage {
        // 1. stride = cellPx >= 4 ? 1 : (cellPx >= 2 ? 2 : 4)  (cellPx = width*dpr/360)
        // 2. filtro por célula: col = floor(lon+180), row = floor(90-lat); col%stride==0 && row%stride==0
        // 3. para cada dot mantido: t = SunShading.intensity(lat, lon, now)
        //    cor = lerp(#111111, #FF9800, max(0.10, t))
        // 4. UIGraphicsImageRenderer: fundo #111111, círculos de raio
        //    max(1, round(cellPx*stride*0.5)/2) px físicos
        // 5. posição: x = (lon+180)/360 * width*dpr (snap ao pixel), y = (90-lat)/180 * height*dpr
    }
}
```

**Decisões de renderização (copiar do app):**
- Eixo: lon -180..180 → x 0..width; lat 90..-90 → y 0..height (equiretangular 2:1)
- Snap ao pixel físico: `(x*dpr).rounded() / dpr`
- Raio: `max(1, round(cellPx * stride * 0.5)) / dpr` (mesma fórmula do app — gap ≈ dot)
- Brilho mínimo noturno: `max(0.10, t)` (mistura com o fundo)
- Cores: fundo `Color(red: 17/255, green: 17/255, blue: 17/255)`; dia `Color(red: 1, green: 152/255, blue: 0)`; noite = lerp para o fundo
- Cache: imagem cacheada em memória por (minuto, tamanho) — o provider recarrega a cada 30 min, mas a VIEW pode re-render por outros motivos; evitar regerar a imagem à toa

**Verificação:**
- Gerar a imagem do renderer num script swift de linha de comando (salvar PNG em /tmp) e comparar VISUALMENTE com o golden do app (mesmo instante UTC e mesmo tamanho) — os continentes devem coincidir dot a dot
- Commit: `feat: world dot map renderer in Swift (parity with Flutter)`

> **Pitfall:** WidgetKit tem budget de render. Se o sistema mostrar placeholder ("Widget failed to render") com o Canvas direto, a mitigação é: renderizar a imagem NO PROVIDER (uma vez por reload de 30 min) e o widget só exibe `Image(uiImage:)` — renderização trivial. Projetar o renderer já como `UIImage` (como acima) justamente para permitir os dois caminhos.

## Riscos / Trade-offs / Open Questions

1. **Budget de render do WidgetKit**: risco principal. Mitigação desenhada: renderer produz `UIImage` (renderizar no provider a cada 30 min, view só exibe a imagem). Se ainda estourar, reduzir dots com stride maior no widget.
2. **Reimplementação em Swift**: ~150 linhas novas, mas port direto com verificação de paridade (números e pixels) — sem adivinhação.
3. **pbxproj**: nunca editar à mão; nunca re-rodar `flutter create .`.
4. **Deployment target**: widget exige macOS 14+; app mantém 10.15 (o widget simplesmente não aparece em Macs < 14). Sem impacto para o usuário (macOS 26).
5. **Dataset duplicado** (assets/ + bundle do widget): 193 KB a mais no bundle — irrelevante. Manter os dois em sincronia (README nota).
6. **Open**: preenchimento do mapa no widget — `scaledToFill` (preenche, corta bordas) vs `scaledToFit` (cabe inteiro, fundo nas laterais). Decidir visualmente na Task 6.
